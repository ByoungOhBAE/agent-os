## 3. 목표 · 하지 않을 것

**목표**
1. `orca/workspaces`에 **바탕(업무 시스템)** 을 깐다: 프로젝트 명부 하나, 바탕 대문, 공용층 목록.
2. **새 프로젝트 시작 / 보관**을 바탕에서 한 번에 한다.
3. 다른 목록들(Hermes 프로젝트·AgentOS 작업계획·Paperclip)은 **명부를 따라가게** 하고, 어긋나면 매주 알린다.
4. 바탕 → 프로젝트 → 문서로 내려가는 길잡이(영상의 세컨드 브레인)를 만든다.
5. 이 구조를 한 화면으로 본다(시안 A/B/C, 영상과 다른 디자인).

**하지 않을 것**
- 프로젝트 안의 일(학원 화면·봇 설정)을 바탕으로 옮기기 — 바탕은 **목록·규칙·길잡이·공용층**만 가짐
- 폴더 이동·삭제·git 병합(예전 git 통합 초안은 별도)
- 학원 숫자(상담·출석)를 바탕 화면에 띄우기 — 나중에 「프로젝트가 바탕에 요약을 내주는 창구」로(아래 「나중에」)
- 메일·캘린더 연결, 24시간 PC, 클라우드 비서

## 4. 바탕의 생김새

```
C:\Users\tahar\orca\workspaces\
├─ AGENTS.md            ← 바탕 대문(이 폴더에서 연 모든 채팅이 읽음): 명부 요약 · 찾는 법 · 공용 규칙
├─ work-system\         ← 바탕 본체(비공개 GitHub 저장소)
│   ├─ projects.json    ← 프로젝트 명부(유일한 원본)
│   ├─ 프로젝트\<이름>.md ← 프로젝트별 안내 카드(자동 + 손글씨 몇 줄)
│   ├─ 색인\             ← 매일 자동 생성: 문서 한 줄 = 제목·상태·경로·날짜
│   ├─ templates\       ← 새 프로젝트 규칙 파일 틀
│   ├─ scripts\         ← new-project · archive-project · sync-check · build-index · find
│   └─ app\             ← 바탕 화면(4단계)

├─ agent os\            ← 자식
├─ rimbus company project\ ← 자식
└─ …
```

명부 한 줄(예): `{ id, 이름, 폴더, 종류(사업·AI도구·회사·실험·보관), GitHub(공개/비공개/없음), 배포(없음/NAS), 상태(진행/보관), 작업 사본[], 규칙 파일, 관련 스킬 분류, 시작일 }`

- 바탕 대문을 `orca/workspaces/AGENTS.md`(저장소 밖 파일 1개)로 두는 이유: Hermes는 채팅을 연 폴더의 규칙 파일을 읽는다. 지금 이 채팅도 그 폴더에서 열렸다. 대문 본문은 `work-system/`의 명부에서 자동으로 만들고, 바깥 파일은 그 사본.
- 바탕 본체 이름 `work-system`(영문: 스크립트·도구가 한글 경로에서 자주 깨짐 — 내가 정함).
- 비공개 저장소인 이유: 명부에 비공개 프로젝트 이름·경로가 들어감. agent os(공개)에는 넣지 않음.

## 5. 단계

### 0단계 · 바탕 깔기
- `work-system` 폴더 + 비공개 GitHub 저장소, `projects.json`을 실측(`registry-seed.json`)에서 채움 → 사장님이 종류·이름만 확인.
- 바탕 대문 `AGENTS.md` 자동 생성(명부 요약 표 · 찾는 법 · 공용 규칙: 커밋·푸시, 비밀값, 자료실).
- 관문 W1 명부 폴더 = 실제 폴더(따로 셈) · W2 새 채팅(`env -u TERMINAL_CWD`, cwd=workspaces)에서 「우리 프로젝트 뭐 있어?」→ 명부대로 답(대화 기록) · W3 agent os 저장소에 비공개 경로가 새로 안 들어감.

### 1단계 · 새 프로젝트 시작 / 보관
- `new-project`(스크립트 + Hermes 스킬, 화면 단추도 같은 스크립트를 부름) 한 번에:
  1. 폴더 2. 규칙 파일 틀(.hermes.md) 3. git + GitHub(공개/비공개/없음) 4. 명부 등록 5. `hermes project create` 6. AgentOS 작업계획 등록(명부를 읽게 바꿈) 7. 색인 자리 (+ 배포 NAS면 배포 메모 자리)
- 미리보기 먼저(만들어질 것 목록) → 확인 → 실행, 중간 실패 시 이미 만든 것 되돌림.
- `archive-project`: 명부 상태=보관, Hermes 프로젝트 보관, 화면·색인에서 숨김. **폴더는 지우지 않음.**
- 관문 N1 시험 프로젝트 `zz-시험`을 만들고 7곳 모두 등록 확인 → 보관 → 지움(GitHub 시험 저장소도) · N2 3번에서 일부러 실패시키면 1·2가 되돌려짐 · N3 같은 이름 두 번 → 거절.

### 2단계 · 명부 맞추기 점검
- `sync-check`: 명부 ↔ 폴더 / Hermes 프로젝트 / AgentOS 작업계획 / Paperclip(켜져 있을 때) / 루틴의 작업 폴더 / GitHub.
- 매주 월 09:10 Hermes 루틴, 어긋남만 짧게 보고. 고치기는 사장님 「맞춰」 한마디 뒤(자동으로 고치지 않음).
- AgentOS `DEFAULT_FOLDERS`를 명부 읽기로 바꿈(회사 프로젝트를 일부러 뺀 결정은 명부에 「AgentOS에서 숨김」 표시로 보존).
- 관문 S1 지금 상태에서 어긋남 = 실측표(Hermes 2 · AgentOS 1 · 빈 폴더 3) · S2 Paperclip 꺼짐 → 「확인 불가」(0개라고 하지 않음).

### 3단계 · 길잡이(세컨드 브레인)
- 바탕 대문 → `프로젝트\<이름>.md`(이 프로젝트의 대문 위치·주요 계획·배포·자주 쓰는 스킬) → `색인\<이름>.md`(자동, 100줄마다 나눔) → 실제 문서.
- `find <낱말>`: 모든 프로젝트 색인을 한 번에 찾음. 매일 03:50 색인 새로.
- 관문 B1 색인 줄 수 = 원천 문서 수(따로 셈) · B2 새 채팅에서 「할인 세칙 어디?」「봇 백업 결과 어디?」「회사 설계 문서 어디?」 3문항이 대문→프로젝트→색인 순서로 맞는 경로(대화 기록) · B3 깨진 링크 0.

### 4단계 · 바탕 화면
- 맨 위 = 바탕(공용층 숫자 + 자식 프로젝트 + 명부 어긋남 + 「＋ 새 프로젝트」), 프로젝트를 누르면 상세(대문·계획서 상태·이 프로젝트 루틴·작업 사본·공용층에서 쓰는 것).
- 화면은 `work-system/app` — 이 PC에 로그인하면 켜지는 작은 화면(Paperclip·AgentOS와 무관, 바탕화면 아이콘 하나). 다른 프로젝트 화면에는 「업무 시스템으로」 링크만.
- 데이터는 모두 `work-system`의 명부·색인·점검 결과에서 읽음. 쓰기는 「새 프로젝트/보관」 두 단추뿐(1단계 스크립트 호출, 미리보기·확인 거침).
- 관문: 시안 v2와 같은 점검(어긋남 숫자 = 따로 계산, 확인 불가 표시, 상세 이동 경로, 1440/390 넘침 0) + 실제 데이터 화면을 직접 봄.

- AgentOS 「프로젝트 허브」를 바탕으로 키우기 — 이미 프로젝트 탭이 있어 빠르지만, 공개 저장소라 비공개 프로젝트 목록을 둘 수 없고 Paperclip에 묶임. 대신 AgentOS 허브는 바탕 명부를 읽는 쪽으로 바꿈(2단계).
- 분야별 길잡이(v1: 학원·광고·AI…) — 사장님 구조는 「프로젝트별」. 분야는 프로젝트 안의 소제목으로.
