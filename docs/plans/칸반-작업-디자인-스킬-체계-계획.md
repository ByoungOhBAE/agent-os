# 칸반·작업 화면 디자인 스킬 체계 — 계획 (초안, 미승인)

작성: 2026-10-04 · 상태: **초안 — 사장님 승인 전. 코드·스킬 설치 변경 없음.**
요청: "에이전트 오에스의 칸반과 작업 메뉴가 사용자가 보기에 너무 불편한 게 많아. 사용자가 직관적으로 정보를 파악할 수 있게 도움이 되는 디자인 스킬을 찾고 분류·정리하도록 구조를 짜고 싶어"

## 1. 확인한 사실 (2026-10-04 실측)

| 항목 | 사실 |
|---|---|
| 대상 화면 | Paperclip(3100) 안의 프로젝트 허브 **칸반**(주입 뷰, `GATES-kanban.md`, `plugins/agentos-project-hub`)과 Paperclip 기본 **작업** 목록. `DESIGN.md`에 칸반 규칙은 한 줄뿐(컬럼=상태, 카드=제목·담당·우선순위·상태) |
| 기존 검증 | 칸반 게이트는 "동작함·가로 넘침 없음"만 확인. **읽기 쉬움·한눈 파악**을 재는 게이트는 없음 |
| 이미 설치된 디자인 스킬 | `web-design-guidelines`, `interface-design`, `frontend-design`, `design-taste-frontend`, `redesign-existing-projects`, `popular-web-designs`, `design-md`, `review-animations`, `omh-design-quality-gate`, `omh-visual-qa`, `omh-accessibility-audit`, `dogfood` — **역할이 겹치고, 어떤 상황에 어느 것을 쓸지 정한 기준이 없음** |
| 외부 후보 (skills.sh 설치 수 / GitHub 별) | 아래 3장 표 |

## 2. 목표 / 하지 않는 것

**목표**: "이 화면의 무엇이 불편한가 → 어떤 스킬로 진단·개선하나"가 바로 연결되는 **스킬 지도 + 안내 스킬 1개**를 만든다.

**하지 않는 것**
- 칸반·작업 화면 코드 수정 (진단 결과가 나온 뒤 **별도 계획**으로)
- Paperclip 본체 수정
- `npx skills add` 로 다른 에이전트 폴더에 설치 (Hermes는 고정 커밋의 SKILL.md를 검토 후 `skill_manage`로만 설치)
- 랜딩페이지용 "고급스러운 외형" 스킬로 업무 화면 꾸미기

## 3. 분류 체계 — "사용자가 묻는 질문" 기준 6칸

| 칸 | 사용자 눈높이 질문 | 이미 있음 | 외부 후보 (검토 대상) |
|---|---|---|---|
| ① 진단 | 무엇이 왜 불편한가? | `dogfood`, `omh-visual-qa`, `web-design-guidelines` | `pbakaus/impeccable` (critique·audit 모드, 31만 설치, ★75k, Apache-2.0) |
| ② 정보 위계 | 무엇을 먼저·크게 보여줄까? 덜어낼 건? | `interface-design` | `impeccable` (clarify·distill 모드), `nextlevelbuilder/ui-ux-pro-max` (대시보드·차트 규칙 DB, 38만, ★133k, MIT) |
| ③ 시각 표시 | 상태·우선순위·담당 봇을 색·아이콘·배지로 어떻게 구분? | `design-md`, `DESIGN.md` 토큰 | `ui-ux-pro-max` |
| ④ 조작·전환 | 카드 이동·펼침·필터가 자연스러운가? | `review-animations` | `emilkowalski/emil-design-eng` (32만, ★43k, MIT) |
| ⑤ 가독성·접근성 | 글자 크기·대비·키보드·모바일에서 읽히나? | `omh-accessibility-audit` | `addyosmani/web-quality-skills@accessibility` (5.8만, ★2.9k, MIT), `ibelick/ui-skills@fixing-accessibility` (2만, ★9k, MIT) |
| ⑥ 검증 | 고친 뒤 실제 390/768/1440 화면에서 좋아졌나? | `omh-design-quality-gate`, `agentos-dashboard-development`의 local-ui-qa | — |

**제외 후보 (사유 기록)**: `taste-skill`의 high-end-visual-design·gpt-taste(랜딩 외형용), `anthropics/canvas-design`(포스터), `uizze ios-design`(iOS 전용), `wshobson grafana-dashboards`(Grafana 전용), `lark-*`(Lark 전용). "kanban"·"task board" 검색 결과에는 칸반 UX 전용 스킬이 **없었음**.

## 4. 만들 구조

```
hermes skills/
  design/agentos-board-ux/          ← 새 안내(라우터) 스킬 1개
    SKILL.md                        질문 → 칸(①~⑥) → 쓸 스킬 최대 2~3개
    references/skill-map.md         전체 지도: 출처·고정 커밋·라이선스·설치 수·역할·채택/보류/제외+사유
    references/board-checklist.md   칸반·작업 화면 전용 점검표
                                    (카드 5초 파악, 상태·담당 봇·막힘 표시, 빈 상태, 밀도, 한국어 용어, 모바일)
    references/pain-inventory.md    실측 불편 목록 ↔ 담당 칸 매핑
```
- 겹치는 스킬은 칸마다 **주 스킬 1개 + 보조**로 정해 중복 실행을 막는다.
- `agentos-dashboard-development` 스킬에 "디자인 판단은 agentos-board-ux 경유" 한 줄 연결.

## 5. 단계

| 단계 | 내용 | 산출물 |
|---|---|---|
| P0 불편 실측 | 실제 칸반·작업 화면을 390/768/1440에서 캡처 + 사장님 불편 사항 수집 → 항목별로 ①~⑥ 분류 | `pain-inventory.md`, 캡처 |
| P1 후보 검증 | 외부 후보 4~5개를 고정 커밋으로 SKILL.md 원문 읽기: 실행 스크립트·네트워크 호출 유무, 라이선스, 기존 스킬과 중복 | `skill-map.md` (채택/보류/제외) |
| P2 설치·정리 | 채택분만(최대 3개) `skill_manage`로 설치, 안내 스킬·점검표 작성 | 스킬 폴더 |
| P3 시범 진단 | 안내 스킬로 실제 칸반을 진단 → 개선 제안 보고서(코드 수정 없음) | 진단 보고서 → 다음 개선 계획의 입력 |

## 6. 완료 기준

- [ ] P0의 모든 불편 항목이 ①~⑥ 중 한 칸과 주 스킬 1개에 연결됨 (빈 칸 0)
- [ ] 외부 스킬 전부 고정 커밋 SHA·라이선스·검토 결과가 `skill-map.md`에 있음, 제외 후보도 사유와 함께 남음
- [ ] 한 질문에 안내 스킬이 부르는 스킬 ≤ 3개, 칸마다 주 스킬 1개
- [ ] P3 진단이 **실제 화면 캡처**를 근거로 함 (합성 화면·추측 금지)
- [ ] 문서·스킬 변경은 커밋 + 푸시 (agent-os는 공개 저장소 → 비밀값 검사)

## 7. 열린 질문 (승인 전 확인)

1. 가장 불편한 점 2~3개 (예: 카드에 정보가 너무 많음/적음, 상태 구분이 안 됨, 어느 봇이 하는지 모름, 막힌 작업이 안 보임, 모바일에서 안 보임)
2. 대상 범위: 프로젝트 허브 칸반 + Paperclip 기본 '작업' 목록 둘 다인지
3. 외부 스킬 신규 설치 상한 3개로 괜찮은지
