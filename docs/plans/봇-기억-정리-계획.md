- "봇이 직접 넣은 항목" = 봇이 일하면서 memory 도구로 저장했지만 아직 공통·프로젝트·봇 전용 지식(registry)으로 분류되지 않은 것.
- 한도에 거의 찬 봇 5~7개는 **새 교훈을 저장할 자리가 거의 없음**.
- 정리 프로그램(`apply`)은 이 상태에서 한도 초과로 **스스로 멈춤**(아무것도 쓰지 않음). 그래서 2026-10-05 스킬 갱신은 기억을 건드리지 않는 `apply-skills`로 했다.
- 봇 기억 원문은 공개 저장소에 적지 않는다(agent-os는 PUBLIC). 항목별 분류표는 저장소 밖 `%LOCALAPPDATA%/agentos/memory-cleanup/`에 둔다.

## 2. 목표
1. 봇이 직접 넣은 항목 66개를 하나씩 분류한다.
   - **여러 봇에게 쓸모** → registry의 공통/프로젝트 지식으로 옮김(자동 로딩 스킬이 되어 기억 자리를 차지하지 않음)
   - **그 봇만의 교훈** → 봇 전용 지식(`agentos-bot-<봇>`)으로 옮기거나 기억에 남김
   - **끝난 작업의 진행 기록·지금은 틀린 사실** → 지움(백업은 보관)
2. 모든 봇의 기억이 한도의 70% 이하가 되게 해서 새 교훈을 저장할 자리를 만든다.
3. 정리 뒤 `status`가 기억 포함 STATUS_OK.

## 3. 하지 않는 것
- 봇에게 스스로 기억을 지우라고 시키지 않는다(가드가 막고, 결과를 검증하기 어렵다).
- 사실 내용을 새로 지어내지 않는다. 옮길 때 문장은 그대로 두고, 틀린 사실만 고쳐 쓴다(이유를 표에 적음).
- 기억 한도(2,200자) 자체를 늘리지 않는다.

## 4. 진행 순서
1. 항목 분류표 작성(옮김/남김/지움 + 이유) → **사장님 확인** (지울 항목은 원문 첫머리를 보여 드림).
2. 백업(프로그램 내장 + 별도 해시 기록).
3. registry 수정 → `check` → `plan`으로 봇별 크기 확인(모두 70% 이하).
4. `apply` 실행.
5. 검증: 봇별 기억·스킬이 plan과 같음(`status` STATUS_OK), 옮긴 항목이 해당 스킬 파일에 들어 있음, 지운 항목이 백업에 있음, 봇 한 개에 실제 대화로 옮긴 지식을 아는지 확인(게이트웨이 정상일 때).

## 5. 결정이 필요한 것
- 지울 항목(끝난 작업 기록 등)을 지워도 되는지 — 분류표를 보고 결정.
