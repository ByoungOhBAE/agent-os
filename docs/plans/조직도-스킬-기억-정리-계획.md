## 2. 목표
1. 조직도 봇 카드에서 **기억 사용률·분류 대기 수·스킬 수**를 한눈에 본다.
2. 봇 기억의 미분류 항목을 화면에서 **옮김/남김/지움**으로 분류하고, 미리보기 → 백업 → 적용 → 다시 읽기 확인까지 한 흐름으로 한다. 결과: 모든 봇 기억 ≤ 70%, `status` STATUS_OK.
3. 부서 역할별 **스킬 묶음(프리셋)** 으로 무관한 스킬을 끈다. 효과는 실제 봇 턴의 스킬 목록 크기로 잰다.

## 3. 하지 않는 것
- 봇에게 자기 기억·스킬을 고치게 하지 않는다(가드가 막고 검증 불가). 쓰기는 운영자 → BFF → 스크립트.
- 기억 한도(2,200자)를 늘리지 않는다. 기억 문장을 새로 지어내지 않는다(틀린 사실만 고치고 이유 기록).
- 스킬 파일을 지우지 않는다 — `skills.disabled`로 끄기만(되돌리기 쉬움).
- 등록 안 된 확인봇 프로필 삭제는 이 계획 밖(목록 표시만).
- 봇 기억 원문을 공개 저장소·문서·커밋에 넣지 않는다(§6 결정 1 전까지).

## 4. 단계

### 1단계 — 보기 전용 (위험 낮음)
- BFF `GET /api/hermes/knowledge/status`: 봇별 기억/USER 글자 수·한도, carried 수, DRIFT, 스킬 층(자동 로드·agentos·로컬·외부·꺼짐 수). 로직은 `server/knowledge-status.mjs` 순수 함수 + vitest.
- 조직도 구성원 카드에 배지: `기억 2185/2200`(≥85% 빨강, ≥70% 주황), `분류 대기 12`, `스킬 4+81+103`. 클릭 → 「스킬·기억」 상세(층별 목록, carried 항목 첫머리).
- 조직도 아래 「조직도 밖 프로필」 접힌 목록(확인봇 등).
- **쓰기 0**: 전후 모든 프로필 MEMORY/USER/config/SOUL 해시 동일이 게이트.

### 2단계 — 기억 분류·적용 (이전 초안 흡수)
- 상세 창에서 carried 항목마다 `공통 / 프로젝트 / 봇 전용 / 남김 / 지움` 선택 → 결정은 **저장소 밖** `%LOCALAPPDATA%/agentos/memory-cleanup/decisions.json`에 초안으로만 저장.
- 「미리보기」: 결정 반영한 `plan` → 봇별 적용 후 크기 표시. 70% 넘는 봇이 있으면 적용 버튼 잠김.
- 「적용」(CEO·비서실장만): 백업 → registry 반영 → `check` → `apply` → `status` 다시 읽어 **실측값 표시**(성공 알림 대신 기대값 vs 실제값, "미적용" 배지).
- 지움 항목은 백업에만 남고, 지우기 전 원문 첫머리를 사장님께 보여 확인받는다.

### 3단계 — 역할별 스킬 프리셋
- 부서 역할 4종(콘텐츠 / 개발·디자인 / 검수 / 기획·비서실장)마다 "켜 둘 스킬 범주" 프리셋. 원본은 저장소의 `knowledge/data/skill-presets.json`(스킬 이름만, 비밀 없음).
- 조직도에서 부서 단위 「프리셋 미리보기」 → 봇별 끌 스킬 diff → 적용 = `skills.disabled` 갱신(`hermes -p <p> config set`, HERMES_HOME=루트). 반드시 다시 읽어 diff 확인, `plugins.enabled`·`memory_enabled`·`model.*` 불변 확인.
- 자동 로드(agentos-*)와 SOUL이 이름으로 요구하는 스킬은 프리셋이 절대 끄지 못하게 잠금.

## 6. 결정 (사장님, 2026-10-06 확정)
1. **registry 공개 문제** → **A 채택**: 비공개 덧붙임 `%LOCALAPPDATA%/agentos/knowledge/registry.local.json`(+ 한국어 `ko.local.json`). 봇 기억에서 옮긴 지식은 전부 여기로 가고 공개 저장소에는 들어가지 않는다. 공개 `ko.json`에 있던 봇 기억 번역도 비공개 파일로 옮겼다.
2. 림버스 단체방 봇 4개 → **조직도에 넣음**: 새 부서 「림버스 개발방」(CEO 직속, 작업 폴더 비움 = 지금과 같은 기본 폴더 유지).
3. 콘텐츠 공통 글쓰기 교훈 → **학원 프로젝트 지식으로**(권장안대로 채널마다 다른 규칙은 봇 전용 지식으로 나눔). 학원 프로젝트에 배정된 봇은 7개(콘텐츠 5 + 검수 + 비서실장).
4. 지울 항목 → 분류표를 보고 결정 — **지움 제안 3건은 아직 적용하지 않음**(조직도 화면에서 확인 후 「지움 포함 적용」).

## 7. 버린 대안
- 봇마다 스킬 파일을 지워 정리 → 되돌리기 어렵고 Hermes 업데이트 때 다시 생김. `disabled`가 로컬·외부 모두 숨기므로 충분.
- 기억 한도 상향 → 매 턴 컨텍스트 비용 증가, 근본 원인(미분류 누적) 그대로.
- Hermes 크론으로 주기 정리 → 사장님은 Paperclip 네이티브 루틴을 선호. 필요해지면 주간 "한도 70% 넘은 봇 알림" 루틴을 따로 제안.
