# 작업 계획(Work Plan) 메뉴 — 구현 계획 (초안, 미승인)

작성: 2026-10-03 · 상태: **초안 — 사장님 승인 전. 코드 변경 없음.**
이 문서는 계획이며, 등록·작성 자체가 개발 착수나 실행 승인이 아닙니다.

## 1. 목적 (왜)
비전문가인 사장이 각 워크스페이스 폴더별로 "무슨 일이 남았고 / 예정이고 / 계획만 됐는지"를
전문용어 없이 한 페이지로 보고, 폴더를 클릭해 폴더별로 확인한다.

## 2. 집(위치)
AgentOS 대시보드(`agent os` 리포). 기존 **"작업(업무)" 탭 위에 "작업 계획" 탭 신설**.
근거: 대시보드에 이미 `작업`·`보드` 탭 구조(src/App.tsx)와 `docs/planned-work/BACKLOG.md`
("작업 예정 목록")가 존재. 관리용 내부 화면이므로 고객용 학원 홈페이지가 아니라 여기가 맞다.

## 3. 목표 / 비목표
**목표**
- 폴더 선택기(좌측 또는 상단) → 폴더별 "작업 계획" 한 페이지.
- 3분류 시각화: 🔴 해야 할 일 · 🟡 예정된 작업(승인됨/진행중) · ⚪ 계획만 된 작업(초안).
- 각 항목: 쉬운 말 제목 + 한 줄 설명 + 상태 배지 + 출처 문서.
- 완료(증거 있음) 항목은 참고용으로 접어서 표시.

**비목표(1차)**
- 작업 편집·드래그·새 작업 생성(읽기 전용).
- Paperclip/Kanban 실시간 연동(2차에서 검토).
- 폴더별 권한·인증 분리.

## 4. 데이터 출처 (어떻게 자동 생성)
각 폴더의 계획 문서에서 추출한다.
- 1차 소스: `docs/**/*.md`, `docs/planned-work/BACKLOG.md`, `GATES.md`.
- 분류 규칙(문서 상태줄 기준):
  - ⚪ 계획만: "초안", "미승인", "제안", "승인 전", "과거 제안".
  - 🟡 예정: "승인됨", "진행 중", "승인·진행 중".
  - 🔴 해야 할 일: "일부 구현/P0만 구현 + 남은 예정", BACKLOG "남은 예정" 항목, 게이트 정의됨.
  - ✅ 완료(참고): "실행 완료", "구현·배포 완료", "취소됨".
- 폴더마다 문서 구조가 다르면(예: academy homepage) 폴더별 소스 경로를 설정으로 지정.

## 5. 시각화 스킬 (find-skills 확인 결과)
- find-skills 생태계를 검토함. 외부 설치(`npx skills add`)는 다른 에이전트 디렉터리에 쓰므로 Hermes에 부적합.
- Hermes에 이미 적합한 시각화 스킬이 설치돼 있어 **추가 설치 불필요**:
  - `baoyu-infographic` (信息图/인포그래픽, 21레이아웃×21스타일) — 보스 친화적 한 페이지에 최적.
  - `baoyu-diagram` (아키텍처/플로우/시퀀스/마인드맵 SVG) — 상태 흐름 표현.
  - `architecture-diagram` — 구조 도식.
- 결론: 1차본 페이지는 자체 HTML+테마변수로 구현하고, 풍부한 인포그래픽이 필요할 때 `baoyu-infographic`를 사용.
