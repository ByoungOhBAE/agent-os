# AI 조직 운영 노하우 조사 계획

상태: **승인·실행 완료(2026-09-30)** — 확정: 언어 한+영, 기간 **최근 2개월(2026-08-01 이후)**, 도구 무관, AgentOS 적용 제안 포함. 결과: [ai-org-knowhow-report.md](ai-org-knowhow-report.md).
작성일: 2026-09-30

## 1. 목표

유튜브 영상과 블로그/포스팅 글 가운데, **개인이 여러 AI 에이전트를 조직처럼 구성해(비서실장·전문 봇·승인 체계 등) 효율적이고 정확한 결과물을 만들려는 사람들**의 노하우·방법·스킬을 수집하고, 각 방법을 AgentOS(Paperclip + Hermes 봇, 비서실장 단일 창구) 기준에서 **상세히 설명하는 보고서**를 만든다.

핵심 질문:
1. 그들은 역할을 어떻게 나누는가(오케스트레이터/전문가/검수자)?
2. 정확도를 어떻게 확보하는가(검증 게이트, 증거 요구, 이중 검토, 테스트)?
3. 효율을 어떻게 얻는가(병렬화, 컨텍스트 분리, 스킬/프롬프트 재사용, 메모리)?
4. 실패 사례와 한계는 무엇인가(루프, 환각 전파, 비용 폭증, 승인 병목)?
5. AgentOS에 바로 적용할 수 있는 항목은 무엇이고, 무엇은 근거 부족인가?

## 2. 비목표

- 새 코드 작성, AgentOS 설정 변경, 봇 신규 고용 — 이 계획은 **조사·문서화**까지만이다. 적용은 별도 계획.
- 단일 에이전트 프롬프트 팁(일반 "ChatGPT 잘 쓰는 법") 수집 — 조직/다중 에이전트 관점이 아니면 제외.
- 제품 홍보 영상·광고성 글의 주장 재전달 — 실제 운영 증거(화면, 저장소, 로그)가 없으면 "미검증"으로 표기.
- 유료 강의 구매, 로그인 필요한 커뮤니티 접근.

## 5. 실행 단계(승인 후)

1. **후보 발굴** — 검색어별 결과를 `docs/evidence/ai-org-knowhow/sources.json`에 누적(URL, 제목, 유형, 언어, 날짜). 중복 제거는 코드로.
2. **1차 선별** — 포함 기준: (a) 실제로 2개 이상 에이전트를 역할 분담해 운영, (b) 구체적 방법(프롬프트·구조·게이트) 제시, (c) 결과·실패 언급. 광고·이론만 있는 글 제외. 선별 이유를 표에 기록.
3. **본문 확보** — 유튜브 자막, 글 본문, README 원문을 evidence 폴더에 저장(출처 URL 포함).
4. **노하우 추출** — 소스마다 아래 카드 작성:
   - 조직 구조(역할·인원·창구)
   - 정확성 장치
   - 효율 장치
   - 도구 스택
   - 주장의 근거 수준(실제 화면/저장소/로그 있음 · 서술만 · 홍보)
   - AgentOS 적용 가능성(바로 / 수정 필요 / 부적합)과 이유
5. **교차 분석** — 여러 소스가 공통으로 말하는 원칙 vs 소수 의견 vs 상충 의견을 표로 정리.
6. **보고서 작성** — `docs/ai-org-knowhow-report.md`. 구성: 요약 → 공통 원칙 상세 설명 → 소스별 카드 → AgentOS 적용 제안(우선순위·리스크) → 미검증/한계 → 소스 목록.
7. **검증·커밋** — 아래 검증 항목 통과 후 git 커밋(문서·evidence만).

병렬화: 2단계 이후 유튜브 lane / 블로그·GitHub lane / 커뮤니티 lane을 subagent로 나눠 진행 가능(각 lane 결과는 동일 JSON 스키마로 반환). 실행 시 각 lane의 모델·프롬프트를 상태 메시지에 표시한다.

## 6. 수용 기준

- [ ] 최종 소스 **20편 이상**, 그중 유튜브 8편 이상, 한국어 자료 5편 이상(A1 유지 시).
- [ ] 모든 소스에 URL·날짜·근거 수준이 표기되고, 본문/자막 원문이 evidence 폴더에 있다.
- [ ] 각 소스 카드가 6개 항목(구조·정확성·효율·도구·근거·적용성)을 빠짐없이 채운다.
- [ ] 공통 원칙이 최소 5개 도출되고, 각 원칙마다 뒷받침 소스 2개 이상이 링크된다.
- [ ] 보고서가 "주장"과 "관찰된 증거"를 구분해 표기한다(홍보·서술만인 소스는 명시적으로 낮은 신뢰도).
- [ ] AgentOS 적용 제안 각 항목에 현재 구조와의 차이점과 리스크가 적혀 있다.
- [ ] 사용자가 요청한 "상세하게 설명" 충족: 각 노하우는 *무엇을·왜·어떻게(구체 절차/프롬프트 예)* 3요소를 포함한다.

## 7. 검증 방법(최소)

- `sources.json` 개수·유형·언어 집계를 스크립트로 출력해 수용 기준 수치와 대조.
- 보고서 내 URL 전부에 대해 HTTP 상태 확인(200/리다이렉트) 스크립트 실행 → 결과 표 첨부.
- 카드 필수 항목 누락 검사(간단한 마크다운 파서 스크립트).
- 사용자 스팟체크: 임의 소스 3개를 골라 카드 내용이 원문과 일치하는지 확인 요청.
