> **현재 기준 (2026-09-28):** 실제 비서실장은 `hermes_gateway`로 전용 Hermes 프로필에 연결되어 있으며, 새 봇도 `scripts/hermes-bots.mjs hire`로 생성합니다. 아래 Claude/Paperclip 봇 및 초기 스킬 표는 **전환 전 당시 기록**입니다. 기존 요청→계획→사용자 승인→위임→검토→보고 순서는 유지합니다. 스킬 동기화는 Paperclip의 desired 목록이 아니라 Hermes 프로필에서 검증합니다. [재검수 근거](../plugins/agentos-youtube/OPERATIONS-AUDIT.md).

상태: **구현·배포·실제 시험 완료 (2026-09-27).** 결과는 맨 아래 "9. 결과" 참조.
요청 원문: "사용자가 직접 소통하는건 비서실장 봇을 통해서만 작동해야해 비서실장이 내 요구사항을 들으면 오엠에이치 플랜 스킬을 사용해 계획을 수립하고 요구사항에 필요하다면 부서와 봇을 만들고 부서명_담당업무 이름을 붙이고 역할을 분배하고 작업 지시,감독을 하고 최종결과를 받으면 내게 보고하는 프로세스를 구현하고 싶어"

## 1. 목표 / 비목표

목표
- G1 사용자는 **비서실장 창구 하나**에서만 요청·승인·보고를 주고받는다.
- G2 비서실장은 요청마다 **omh-plan 형식의 계획**(목표·비목표·가정·완료 기준·검증 방법)을 쓰고 사용자 승인을 받는다.
- G3 승인 뒤 필요하면 **부서와 봇을 만들고** 봇 이름을 `부서명_담당업무`로 붙여 조직 배치도에 넣는다.
- G4 작업을 쪼개 봇에게 **지시**하고, 결과가 오면 **검토(감독)** 하고, 부족하면 다시 시킨다.
- G5 끝나면 **최종 보고**를 창구에 남기고 사용자에게 알린다.

비목표(이번에 안 함)
- 기존 Hermes 봇 16개를 비서실장이 직접 부리는 것(Hermes 봇 연결은 다음 단계).
- 데스크톱 앱 방, 학원 홈페이지 콘텐츠 생성 흐름 변경.
- 새 봇의 외부 서비스 로그인, 결제, 인터넷 공개.

| 항목 | 확인 결과 |

| 봇 만들기 | Paperclip `agent-hires`: 비서실장이 만든 봇은 **비서실장의 구독 연결을 물려받음**(서버 코드 `defaultAiConnectionForHire`) |

→ 새 엔진을 만들 필요 없이 **Paperclip 기본 기능 + 비서실장 지시문 + 화면 정리**로 구현한다.

## 3. 흐름

```
사용자 ─(요청)→ 비서실장 창구 ─→ Paperclip 작업 "요청: …" (담당 비서실장)
비서실장: omh-plan 형식 계획 → 계획 문서 저장 → 확인 요청
사용자: 창구에서 [승인] 또는 [수정 요청]
비서실장: 부서 만들기(조직 배치도) → 봇 만들기 `부서명_담당업무` → 배치
        → 하위 작업 지시(순서 있는 건 선행 작업 연결)
봇들: 작업 → 결과 제출 → 비서실장 자동 호출
비서실장: 검토 → 부족하면 재지시 / 충분하면 최종 보고 → 요청 완료
사용자: 창구에서 보고 확인
```

## 4. 만들 것

1. **비서실장 지시문 확장** — 이미 있는 조직 배치도 블록 옆에 "단일 창구 운영 규칙" 블록 추가(플러그인이 관리, 원문 보존).
   - 계획은 omh-plan 항목 그대로, 승인 전엔 봇 만들기·지시 금지.
   - 봇 이름 규칙 `부서명_담당업무`(예: `콘텐츠_블로그작성`), 같은 역할 봇이 있으면 재사용.
   - 한 요청당 새 봇 최대 수, 봇 설정(구독 Opus 5.5, 예약 실행 끔, 작업 폴더 분리, 시간 제한).
   - 검토 기준: 계획의 완료 기준을 하나씩 확인, 최대 재지시 횟수 넘으면 사용자에게 보고.
   - 최종 보고 형식: 쉬운 한국어, 결과물·한 일·확인 못 한 것.
2. **스킬 연결** — `omh-plan`을 회사 스킬로 가져와 비서실장에게 연결(+ Paperclip 기본 `paperclip-create-agent`, `paperclip-converting-plans-to-tasks`).
3. **창구 화면(통합 관제)** — "비서실장" 창구를 맨 위에:
   - 요청 쓰기 → 비서실장 작업 생성.
   - 요청 목록과 단계 표시: 계획 중 / 승인 대기 / 진행 중(부서·봇·하위 작업 진행률) / 보고 완료 / 막힘.
   - 계획 보기 + [승인] [수정 요청] 버튼, 최종 보고 보기.
   - 다른 봇: **대화 입력 잠금**(진행 보기 + 긴급 중지만).
4. **이름 규칙 검사** — 비서실장이 만든 봇 이름이 규칙을 어기면 창구에 경고.
5. **검증 도구** — 단위 테스트, 화면 점검(1440/768/375), 실제 요청 1건 끝까지 시험.

## 5. 완료 기준

- A1 창구에서 요청 → 비서실장 작업이 생기고 비서실장이 깨어난다.
- A2 계획 문서가 omh-plan 항목(목표·비목표·가정·완료 기준·검증)을 모두 갖고, 승인 전엔 새 봇·하위 작업이 0개.
- A3 승인 후 만든 봇 이름이 모두 `부서명_담당업무` 규칙, 조직 배치도의 그 부서에 배치.
- A4 하위 작업이 봇들에게 배정되고, 끝나면 비서실장이 자동으로 깨어 검토한다.
- A5 최종 보고가 창구에 표시되고 요청이 "완료".
- A6 다른 봇 대화 입력이 잠겨 있고 긴급 중지는 된다.
- A7 운영 데이터 보존(기존 회사·작업·봇 개수 대조), 비밀값 노출 0.

## 6. 위험

| 위험 | 대응 |
|---|---|
| 봇이 너무 많이 생김 | 요청당 새 봇 상한, 같은 역할 재사용 |
| 구독 사용량 소모 | 예약 실행 끔, 실행 시간·횟수 상한, 시험은 작은 요청 1건 |
| 비서실장이 승인 없이 진행 | 지시문 + 검사(승인 전 하위 작업 0개) |
| 봇들이 같은 폴더를 건드림 | 봇마다 작업 폴더 분리 |
| omh-plan이 Hermes 전용 표현을 가짐 | 가져올 때 내용 확인, 필요한 항목만 지시문에 명시 |

알아둘 점
- 비서실장이 만든 봇은 구독(Claude Opus 5.5)을 물려받고 예약 실행은 꺼져 있다. 요청 하나당 새 봇 최대 3개, 같은 역할은 재사용.
