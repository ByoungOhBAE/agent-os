# 계획 — 홍보 콘텐츠 시나리오 10건 실전 시험 + 채용 검수 게이트 (초안, 미승인)

상태: **실행 완료(2026-10-01 07:35)** — HER-33 done, 작업 21건 검수 통과, 함정 7/7 통과. 결과·문제·개선안: `docs/evidence/scenario-run/report.md`.

## 목표
1. 요리학원 수업 상황 시나리오 10건(짧은 것~긴 것)을 봇 조직에 주고 인스타·블로그·당근마켓 홍보글을 만들게 한다. 그 과정(배정·검수·반려·완료 보고·guard 이벤트)을 자동으로 기록·채점하고, 틀린 곳을 고친다.
2. 그 과정에서 비서실장이 **새 봇을 채용**해야 하는 상황이 자연스럽게 생기므로(블로그 본문·당근 담당 봇이 없음), 채용을 검수하는 장치를 먼저 만든다.

## 비목표
- 사진 생성(이미지 생성 도구 없음). 시나리오의 "사진"은 글로 된 사진 설명이다.
- 실제 SNS 게시. 결과물은 Paperclip 문서로만 남긴다.
- 문구 품질의 자동 채점. 형식·절차는 자동, 글의 좋고 나쁨은 사장님 눈.

## 확인한 사실
- 워커: 콘텐츠_SNS문구(인스타), 콘텐츠_블로그제목(제목만), 콘텐츠_유튜브분석. **블로그 본문·당근마켓 담당 없음** → 비서실장이 채용해야 함.
- 채용은 `scripts/hermes-bots.mjs hire --name 부서_업무 --role-file <md> --reports-to … --projects …`. 지금 채용을 막는 건 정책 문장("승인 전 채용 금지")뿐이고, **코드로 확인하는 건 없다**. 새 봇 프로필엔 guard도 자동 설치되지 않는다.
- 계획 승인은 Paperclip interaction(request_confirmation)으로 사장님이 누른다. 승인 여부는 API로 읽을 수 있다(accepted + resolvedByUserId).

## 1부 — 채용 검수 게이트 (먼저)

| 장치 | 무엇 | 집행 계층 |
|---|---|---|
| A. 승인 확인 | `hire`에 `--source-issue` 필수. 스크립트가 그 이슈의 plan 승인 카드를 읽어 **사장님 승인(accepted, resolvedByUserId 있음, 봇 승인 아님)** 이 없으면 채용 거부 | 코드(스크립트) |
| B. 역할 파일 검수 | 역할 파일은 승인 이슈의 문서(`role-<영문>`, 첫 줄은 정확히 `# <봇이름>`)로 먼저 올리고, 문서를 마지막으로 고친 뒤 검수 봇이 같은 이슈에 `## 완료` + 문서 키를 적은 댓글을 남긴 뒤 채용(이슈의 review stage 승인만으로는 통과하지 않음). Paperclip 문서 키는 `^[a-z0-9][a-z0-9_-]*$` 만 받으므로 한글 이름 봇은 `hire --role-doc role-<영문>` 으로 문서 키를 지정(생략하면 `role-<봇이름>`, 한글이면 거부). 스크립트는 `--role-file`이 그 문서 내용과 같은지 대조 | 코드 + 검수 봇 |
| C. 자동 안전장치 | 채용 즉시 guard(role=worker, 모드는 현재 워커와 동일) 설치 + 4항목 완료 양식 SOUL(이미 `soulFor`) + 게이트웨이 재시작 안내 | 코드 |
| D. 사후 감사 | `hermes-bots.mjs verify` 확장: guard 없는 봇, 승인 이슈 없는 봇을 표시 | 코드 |

검수 봇이 역할 파일에서 보는 것: 담당 업무가 한 문장으로 명확한가 / 금지 사항(광고법 표현, 지어내기 금지) 있는가 / 완료 기준·결과물 형식 있는가 / 기존 봇과 중복인가.

## 자동 채점(스크립트 `scripts/scenario-run.mjs`)
- 시나리오 JSON → 상위 이슈 1건 생성(비서실장, 계획 승인 1회는 **사장님이 누름**) → 비서실장이 채용·하위 이슈 10건 배정 → 폴링
- 하위 이슈마다 기록: 담당 봇 / 라운드 수 / 반려 사유 / 완료 댓글 4항목 여부 / guard 이벤트 / 소요 시간 / 결과물 문서 링크
- 함정 채점(자동): #2 가격·시간 숫자 없음, #4 후기 원문 포함, #7 모순 언급, #8 금지어 없음, #10 이름 없음
- 결과: `docs/evidence/scenario-run-<날짜>/report.md` + 결과물 전문(사장님이 읽고 품질 판단)
- 끝나면 시험 이슈 전부 `[보관]`

## 순서
1. 1부 A·C·D 구현 + 테스트 → 커밋 (B는 정책 문장 + 검수 봇 SOUL)
2. 시나리오 10건 JSON 작성 → **사장님 확인**
3. 실행(예상 40~60분, 봇 병렬) — 승인 카드 1회 사장님 클릭
4. 보고서 → 고칠 것 목록 → 규칙 수정 → 필요하면 틀린 케이스만 재실행
