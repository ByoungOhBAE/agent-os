## 1. 목표 / 비목표

**목표**
1. Paperclip에서 봇을 만들면 **기본값이 Hermes 봇**이 된다. 비서실장이 채용할 때도 마찬가지다.
2. 지금 Paperclip 봇 6개(비서실장, 콘텐츠_SNS문구, 대시보드개선 3개, 시험봇 1개)를 **Hermes 봇으로 바꾼다**.
3. 모든 Hermes 봇은 **진짜 Hermes 기억**(자기 MEMORY.md + USER.md, Hermes 기억 도구로 스스로 적음)을 가진다. Spike 봇처럼 기억 폴더가 비어 있는 상태는 불합격이다.
4. **Paperclip 화면에서 Hermes 기억을 본다.** 대시보드개선 팀이 만든 "기억 한눈에 보기"를 Hermes 기억 기준으로 맞춰 반영한다.

**비목표**
- Hermes 원본 코드와 Paperclip 원본 코드는 수정하지 않는다. 설정·확장 기능·스크립트만 바꾼다.
- Hermes 게이트웨이(8645)는 재시작하지 않는다. 재시작이 꼭 필요해지면 멈추고 여쭙는다.
- 사장님 Hermes 봇 16개의 기존 기억은 지우거나 덮어쓰지 않는다.
- 유료 API 키 결제로는 돌리지 않는다. Claude 구독(OAuth)만 쓴다.

## 3. 방식 선택

| 안 | 내용 | 기억 | 결제 | 판단 |
|---|---|---|---|---|
| **A. 게이트웨이 연결 (추천)** | Paperclip 봇 1개 = 윈도우 Hermes 프로필 1개. Paperclip은 `hermes_gateway`로 그 프로필에 일을 보냄 | Hermes 기억 그대로. 기존 16개 봇 기억도 바로 씀 | 윈도우 Hermes의 Claude 구독 (F4) | 추천 |
| B. WSL 로컬 실행 | 봇마다 WSL에 별도 Hermes 공간을 만들어 `hermes_local`로 실행 | 새 공간이라 기억이 0에서 시작, 16개 봇 기억과 따로 | WSL 쪽 로그인 필요, 만료 이력 (F9) | 예비안 |
| C. 윈도우 폴더를 WSL에서 직접 실행 | B인데 윈도우 프로필 폴더를 그대로 사용 | 같은 기억 | — | 제외: 두 프로그램이 같은 기억·세션 DB를 동시에 써서 망가질 위험 |

## 4. 흐름 (A안)

1. **연결 확인 (시험 1개)** — 게이트웨이 API 키를 Paperclip 비밀값 저장소에 넣는다(화면·채팅에 값 노출 없음). 디자이너 프로필로 Paperclip 시험 봇 1개를 만들어 작은 일을 시킨다.
   - 확인: 결과가 오고, **Hermes가 기억을 읽고 적는지**, Claude 구독으로 돌았는지, Paperclip 작업 댓글·완료 처리가 되는지.
   - 여기서 막히면(프로필별 주소 미지원·재시작 필요 등) 멈추고 여쭙는다.
2. **Hermes 봇 만들기 기능** — 확장 기능(agentos-control)에 "Hermes 봇 채용" 기능을 추가한다.
   - ① 윈도우에 Hermes 프로필 생성(기존 봇 만들기 경로 재사용, 기억 켜짐, 모델 Opus 5.5 구독) → ② Paperclip 봇 생성(`hermes_gateway`, 그 프로필 주소, 비밀값은 저장소 참조) → ③ 조직 배치.
   - 이름 규칙 `부서명_담당업무`, 비서실장 아래 배치 규칙은 그대로 둔다.
3. **기본값 바꾸기**
   - 비서실장 채용 규칙: 새 봇 = Hermes 봇(2번 기능 사용). Claude 봇 채용 문구 제거.
   - Paperclip 새 에이전트 화면: 기본 선택을 Hermes로(우리 호스트 화면 설정 범위 안에서. 원본 수정이 필요하면 안내 문구로 대신).
4. **기존 봇 6개 전환** — 봇마다 Hermes 프로필을 만들고, 오늘 만든 기억 노트(MEMORY.md)와 사장님 정보(USER.md)를 그 프로필 기억으로 옮긴 뒤 연결을 `hermes_gateway`로 바꾼다.
   - Paperclip 봇 ID·조직 배치·작업 기록은 그대로 유지(설정만 바꿈). 바꾸기 전 설정 백업.
   - 비서실장은 마지막에 바꾼다(창구가 멈추지 않게). 시험봇(Claude Subscription Smoke)은 전환 대신 정리 여부를 여쭙는다.
   - Paperclip 기본 스킬(paperclip, 계획, 채용 등)을 각 Hermes 프로필에도 설치한다.
5. **Paperclip에 Hermes 기억 연결(화면)** — `team/memory-visual` 결과를 Hermes 기억 기준으로 정리해 main에 합치고 배포한다. 봇 카드마다 "Hermes 프로필 기억" 출처를 보여 준다. 쓰기 기능은 넣지 않는다(보기만).
6. **정리** — 흉내 기억 장치(`hermes-memory` 회사 스킬, 기억 블록)는 전환이 끝난 봇에서 뺀다. Spike 봇은 기억 있는 Hermes 봇으로 바꾸거나 정리한다.
7. **실제 시험** — 비서실장에게 작은 요청 1건 → Hermes 봇 채용 → 작업 → 보고까지 확인하고, 각 봇 기억 파일이 실제로 늘었는지 본다.

## 5. 완료 기준

1. 비서실장이 새로 채용한 봇이 `hermes_gateway` 연결이고, 윈도우에 같은 이름의 Hermes 프로필이 있으며 기억이 켜져 있다.
2. 전환 대상 봇이 모두 Hermes 봇이고, Paperclip 봇 ID·조직 배치·지난 작업 기록이 그대로다.
3. 모든 Hermes 봇 프로필에 `memories/MEMORY.md`·`USER.md`가 있고 비어 있지 않다(옮긴 기억 또는 사장님 정보). 기억이 빈 봇은 0개다.
4. 실제 작업 1건 뒤, 일한 봇의 Hermes 기억이 Hermes 기억 도구로 갱신되었다(수정 시각·내용 변화).
5. 봇 실행이 Claude 구독(OAuth)으로 돌았다(API 키 결제 0).
6. Paperclip 화면(Hermes 보기)에서 각 봇의 Hermes 기억 카드가 보인다. PC·태블릿·휴대폰에서 확인한다.
7. 비밀값(게이트웨이 키 등)이 채팅·문서·로그·봇 설정 본문에 없다. 저장소 참조로만 있다.
8. 게이트웨이(8645)를 재시작하지 않았고, 사장님 기존 Hermes 봇 16개의 기억은 바뀌지 않았다(작업을 준 봇 제외).
9. 테스트(확장 기능 tsc·vitest)와 화면 점검이 통과하고 작업 단위마다 커밋되어 있다.

## 8. 선택하지 않은 방법

- C안(윈도우 폴더 직접 실행): 동시 쓰기로 기억·세션 DB 손상 위험.
- 오늘 만든 "흉내 기억"만 유지: Hermes 기억 기능이 아니라서 요청과 다름.
- 기존 16개 Hermes 봇을 Paperclip 봇으로 한꺼번에 등록: 요청 범위(Paperclip 봇 전환·기본값)보다 큼. 필요하면 다음 단계.
