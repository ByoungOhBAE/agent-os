# AgentOS 대시보드 리디자인 — 당시 제안 보존본

상태: **과거 제안**. 아래 초안의 승인·관측 상태는 작성 당시 기준입니다. 현재 관제 소스에는 명패(Seal)가 있지만 이 사실만으로 아래 전체 화면·폰트·배포 기준의 완료를 확정하지 않습니다. 새 기능 작업은 [현재 운영 검수](../plugins/agentos-youtube/OPERATIONS-AUDIT.md)와 실제 소스를 우선합니다.
스킬: interface-design (dammyjay93/interface-design) · omh-plan

## 1. 지금 밋밋한 이유 (운영 3100 캡처로 관찰, 2026-09-26)

| 관찰 | 근거 화면 |
|---|---|
| 초점이 없음 — 에이전트 카드 4장, 지표 4개, 차트 3개가 모두 같은 크기·같은 무게 | `/HER/dashboard` 1440 |

| 같은 데이터 반복 — 대시보드 상단 카드 4장이 모두 "비서실장" | `/HER/dashboard` |

## 2. 방향 (Suggest)

- **사람**: AI 에이전트 회사의 CEO 1명. 아침·틈틈이 열어서 "지금 누가 일하고, 내가 결정할 게 뭔가"를 30초 안에 파악하고 지시를 내린다.
- **동사**: 파악한다 → 결정한다(승인) → 지시한다.
- **느낌**: 야간 상황실의 **집무실** — 조용하고 어둡지만 켜진 불빛(근무 중)만 선명한 곳. 대시보드 템플릿이 아니라 "회사가 돌아가는 소리가 보이는" 화면.

**Domain**: 집무실, 명패, 출근부/근무 표시등, 결재함, 부서, 보고선, 업무일지, 교대
**Color world**: 먹색 책상(`#101716` 유지), 세이지 스탠드 조명(`#bdd1aa` 유지), 놋쇠 명패(따뜻한 황동 — 승인·결재 대기에만), 청회색 모니터 광(진행 중), 한지 메모(보조 텍스트의 따뜻한 회백)
**Signature — 명패(Nameplate) + 근무등**: 모든 에이전트는 어디서든 같은 "명패"로 나타난다 — 모노그램 인장, 이름, 직함·부서, 런타임 각인, 그리고 좌측 근무등(작업 중이면 세이지 빛이 번지고, 대기는 꺼진 등, 멈춤은 황동 점). 대시보드 상단의 "지금 근무 중" 띠, 조직 배치도, 통합 관제 로스터, 에이전트 목록이 모두 같은 명패를 쓴다.
**Rejecting**:
- 동일 KPI 카드 4개 → **오늘의 회사** 히어로 1개 (근무 중 인원 대형 숫자 + 명패 띠 + 결재 대기)
- 테두리만으로 나눈 평면 → **3단 면 체계**(바닥/책상/서류) + 은은한 inset 하이라이트
- 시스템 한글 폰트 → **Pretendard Variable 자체 호스팅**(OFL) + 숫자 tabular, ID는 JetBrains Mono

## 3. 목표 / 비목표

목표
1. 호스트 전역 토큰 재정의(면 3단, 텍스트 4단, 황동 결재 색, 근무등, 서체) — `ui/src/index.css` `.dark` 블록.
2. 대시보드 재구성: "오늘의 회사" 히어로 → 결재·주의 큐 → 활동 차트는 보조 단으로 강등, 중복 에이전트 카드 제거.
3. 명패 컴포넌트를 호스트와 두 플러그인(`agentos.control`, `agentos.org`)에 동일 규격으로 적용.
4. 사이드바: 회사 표식 강화, 현재 위치 레일, 근무 중 인원 배지.
5. 에이전트 목록·통합 관제 빈 상태를 "비어 있음"이 아니라 다음 행동을 주는 화면으로.

비목표
- 라이트 테마 변경, 정보 구조/라우트 변경, 기능 추가(데이터·API 변경 없음).
- 운영 데이터·에이전트 설정 변경. Paperclip 서버 코드 변경.
- 마케팅식 그라디언트·장식 일러스트.

## 4. 가정 (승인 시 확정 필요)

- A1. 잉크/세이지 정체성은 **유지하고 깊이·서체·시그니처를 더한다**(전면 팔레트 교체 아님). ← 사용자 확인 필요
- A2. Pretendard woff2(약 2MB, subset 가능)를 `ui/public/fonts`에 추가해도 된다.
- A3. 범위는 대시보드·사이드바·에이전트 목록·통합 관제·조직 배치도 5화면. 나머지 화면은 토큰 변경의 영향만 받는다.

## 5. 단계 (각 단계 = 커밋 1개, 격리 인스턴스 3199 → 운영 3100)

| 단계 | 내용 | 파일(예상) |
|---|---|---|
| P1 | 토큰·서체: 면 3단, 텍스트 4단, 황동·근무등 토큰, Pretendard 추가 | `ui/src/index.css`, `ui/public/fonts/*` |
| P2 | 명패 컴포넌트(호스트) + 대시보드 "오늘의 회사" 히어로·결재 큐 | `ui/src/components/Nameplate.tsx`(신규), `pages/Dashboard.tsx`, `ActiveAgentsPanel.tsx` |
| P3 | 사이드바·에이전트 목록 명패화 | `components/Sidebar.tsx`, `pages/Agents.tsx` |
| P4 | 플러그인 2종에 같은 명패·토큰 적용, 관제 빈 상태 재설계 | `plugins/agentos-control/src/ui`, `plugins/agentos-org/src/ui` |
| P5 | 운영 반영(백업·행 수·롤백) + `.interface-design/system.md` 저장, `DESIGN.md` 갱신 | 배포 스크립트 재사용 |

## 6. 합격 기준

- 스쿼트 테스트: 1440 대시보드를 흐리게 봐도 "오늘의 회사" 히어로가 가장 먼저 보인다.
- 시그니처 테스트: 명패가 대시보드·사이드바·에이전트 목록·관제·조직도 5곳에 동일 규격으로 나타난다.
- 한글이 Pretendard로 렌더된다(`document.fonts.check` + 계산된 font-family).
- 1440/768/375: 가로 넘침 0, 잘림 0, 콘솔 오류 0, 44px(최소 40) 타깃, 키보드 초점 가시.
- 호스트 UI 테스트·타입체크 통과, 플러그인 테스트 통과, 운영 DB 행 수 전후 동일.
- 전후 스크린샷을 나란히 보여 준다(합성 QA를 운영 증거로 과장하지 않음).

## 7. 검증 방식

`scripts/gate-*-ui.mjs` 패턴의 Playwright 게이트를 대시보드·에이전트 목록용으로 추가, 3199에서 편집 없이 측정 → 운영 읽기 전용 재측정. 호스트는 WSL `pnpm --filter ui typecheck/test/build`.

## 8. 미결 / 거절한 대안

- 전면 새 팔레트(예: 따뜻한 종이색 라이트) — 기존 합의(잉크·세이지 보존)와 충돌해 기본안에서 제외. 사용자가 원하면 A1 변경.
- 글래스모피즘·네온 발광 — 장식용 색이라 거절, 근무등만 제한적으로 빛 사용.
- 대시보드 차트 제거 — 강등만 하고 유지(데이터 손실 없음).

## 9. 승인 후 권장 실행 경로

`ultrawork` 단일 소유 지속 실행 — 한 사람이 P1→P5를 순서대로, 단계마다 게이트·커밋. (토큰이 모든 단계의 선행 조건이라 병렬 레인 이점이 작음.)
