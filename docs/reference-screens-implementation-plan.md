## 3. 제품 결정 (승인 전 제안)

**권장 축:** 기존 AgentOS를 '로컬 운영 허브'로 확장한다. 별도 Paperclip을 복제·설치하거나 Obsidian 볼트를 변경하지 않는다. 먼저 기존 Hermes Kanban·세션·실행 상태를 읽어 Mission Control을 만들고, 메모리는 사용자가 지정한 볼트 경로를 읽기 전용으로 연결한다. Paperclip을 실제 사용하는 경우에만 공식 API 어댑터를 별도 선택지로 제공한다.

- 작업 진실원천: 기본은 **Hermes Kanban**. Paperclip Issues는 독립 네임스페이스 `paperclip:<company>:<issue>`로 읽는다. 수동 링크만 허용하고 자동 양방향 동기화/자동 작업 생성은 보류한다.
- 에이전트 정체성: `runtime / profile / external-agent`와 `provider / model`을 분리. Paperclip의 'Ada'를 Hermes 프로필과 동일시하지 않는다.
- 상태/수치: 항목마다 `source`, `observed_at`, `coverage`, `status`를 가진다. `unknown`, `unavailable`, `unauthorized`, `stale`을 0·성공·실패로 바꾸지 않는다. 비용은 수집한 범위만 합산하고 `partial coverage`를 표시한다.
- 메모리: Obsidian 로컬 vault의 `.md` 노트를 **읽기 전용**으로 검색/목록화. Omi는 별도 API/내보내기 계약이 확인될 때만 연결. Obsidian의 파일 관계(`[[wikilink]]`)와 Omi 관계를 구분하고 원본과 검색 인덱스를 분리한다.

## 4. 단계별 구현 패키지와 완료 기준

### P0 — 진실성·인벤토리 계약 (선행)

1. 에이전트/프로필/보드/실행/볼트/Paperclip의 연결 가능·권한·데이터 출처 목록 작성. 각 소스의 조회 범위와 갱신 방식 명시.
2. BFF의 통합 응답 타입에 `source`, `asOf`, `coverage`, `error`를 정의하고 `GET /api/operations/summary` 같은 **새 계약 후보**를 테스트로 먼저 확정한다. 실제 지원되는 API만 호출하고 백엔드 실패는 카드별로 격리.
3. 키·볼트 경로·Paperclip 인증 정보를 브라우저 응답/URL/로그에서 제외. 설치 상태 체크와 인증/실행 테스트를 분리.

**완료:** 단절된 소스에서도 모르는 값은 `미확인/미집계`, 만료된 값은 시각 포함 `오래된 데이터`로 노출; 기존 관리 화면 회귀 없음.

### P1 — Mission Control 읽기 전용 MVP (우선 권장)

**진행 상태:** 현재 보드 기반 첫 세로 조각 구현·검증. `GET /api/operations/summary`는 Hermes Kanban **현재 보드**의 상태별 수·작업 제목/상태만 노출하며, 화면에서 필터·주의 항목·원본 작업 상세 이동·수동/자동 새로고침을 제공한다. 연결 실패/인증 실패/빈 보드를 0건과 구별한다. 다음 읽기 전용 조각으로 기존 상태/프로필/세션 조회를 활용한 Dashboard·API Server 진단, 프로필 목록의 조회 성공/실패 구분, **선택한 프로필의 최근 세션 최대 4개** 및 원본 세션 상세 이동을 추가했다. 상태·프로필·세션별 마지막 **클라이언트 조회 성공 시각** 및 부분 실패를 표시하며, 화면 숨김 중 30초 폴링을 건너뛰고 복귀 시 새로 조회한다(작업 폴링 수동 일시정지는 유지). 연결 진단은 실행 중인 에이전트 수를 의미하지 않는다. 프로필별 실행 집계, 전체 최근 활동, 검색/Capture, 다중 보드 합산, 비용 계측·외부 플릿 상태는 **아직 미구현**이며 아래 항목은 남은 범위다. 외부 시스템과 자동 쓰기는 하지 않는다.

1. `server/index.mjs`에 현행 Hermes Kanban 보드/작업, Hermes 상태/프로필, 세션/실행 관측을 묶는 BFF 집계. 네트워크 타임아웃·부분 실패·중복 요청/폴링 취소를 테스트.
2. `src/api.ts` 타입과 `src/App.tsx` Overview를 `Work in motion`, `Your attention`, Fleet/연결 진단, 최근 활동으로 확장. 필터 Active/Needs you/Finished/All은 실제 Kanban 상태에 명시적으로 대응시키고, 클릭 시 기존 Kanban/Session 상세로 이동. `Capture`는 기존 작업 생성 흐름으로 연결하되 명시적 확인 후에만 쓰기.
3. 수동 Refresh·일시정지는 이 화면의 **폴링만** 제어(에이전트 실행 중지는 아님); 폴링 숨김 중단/재개, 카드별 수집 시각, 오류 복구를 표시. 체크 분모는 지원 가능한 진단만 포함하고 총괄 성공을 가짜로 계산하지 않는다.

**완료:** 비어 있음/진행/차단/검토/오프라인/인증 실패/부분 데이터에서 상태·출처·이동 대상이 맞고, 0건 카드가 성공으로 오인되지 않음. 원본 Kanban과 집계 수를 테스트 데이터로 대조.

### P2 — 메모리 검색·노트 (옵트인)

1. 볼트 연결 UX에서 사용자가 경로·포함 범위를 선택하고 권한을 확인. 경로 정규화, vault 외부 탈출(심볼릭 링크 포함) 차단, 대용량/숨김/바이너리/비공개 폴더 정책을 먼저 정한다. 로그에는 노트 본문·비밀값 기록 금지.
2. 파일 감시/증분 색인으로 제목·본문 검색, Recent/Notes 및 안전한 미리보기 구현. 검색 결과는 원본 파일 경로와 갱신 시각을 표시하며 삭제·이동·충돌을 재색인으로 반영. 원본은 쓰지 않는다.
3. Graph/Galaxy는 검증된 `[[wikilink]]`만 간선으로, 노트를 노드로 표현. 고립 노트·없는 링크·중복·이름 충돌, 0개 빈 화면, 키보드로 접근 가능한 목록형 대체 화면, 수백 개 노드에서 성능 제한/필터·줌·리셋을 정의. 별 밝기는 최종 수정일 같은 **표시 규칙**일 뿐 기억의 중요도 추론 아님.
4. Omi는 제품/인증/API/데이터 보존 계약 확인까지 비활성; 원격 볼트/Tailscale/MCP/자동 저장·삭제도 별도 단계.

**완료:** 사용자 샘플 vault의 노트/링크 수가 파일 기반 집계와 일치하고, 원본 파일 해시가 전후 동일; 빈 vault, 오류, 파일 변경, 비공개 경로, 375px/키보드 검증.

### P3 — Paperclip/조직도/프로젝트 (선택 통합)

1. 사용자가 실제 Paperclip 인스턴스를 보유하고 연결을 승인하면 로컬 서버의 버전·health·인증·회사 범위·권한과 공식 OpenAPI를 확인. `127.0.0.1:3100` 같은 영상 주소를 하드코딩하지 않는다.
2. BFF 읽기 어댑터로 회사/에이전트/목표/프로젝트/이슈/실행 상태의 **권한 범위 내** 데이터만 취득. 조직도는 실제 `reportsTo` 관계로 구성하고, 아이콘 색/발광은 상태 배지의 대체가 아니게 한다. 링크는 원본 이슈 페이지로; Hermes 보드와 별도 표시.
3. `Assign Task`, `Heartbeat`, `Resume`, config 변경 및 첨부 업로드는 P4까지 숨김. Paperclip이 미설치/연결 불가면 명확한 설정 안내만, 데모 수치/빈 껍데기 조직도는 렌더링하지 않는다.

**완료:** 회사 간 데이터 누출 없음, API 거부·연결 끊김·빈 회사가 구별됨; 목표→프로젝트→이슈 연결과 최근 run이 원본 시스템과 일치.

### P4 — 실행·거버넌스 (명시적 별도 승인)

- Hermes/외부 런타임/Paperclip 각각의 소유자와 실행 계약을 확정. 일시정지/재개/수동 heartbeat/할당은 대상·영향 범위·비용·권한을 보여 준 뒤 승인. 멱등 키, 동시 실행 잠금, 취소 후 상태 재조회, 감사 로그, 예산·작업 폴더 격리. 승인 없이 `24/7 autonomous`를 암시하거나 자동 실행하지 않는다.
- 통합 작업 큐를 새로 만들지 기존 Hermes Kanban과 별개 유지할지 결정 전에는 양방향 상태 변경 불가. Obsidian/Omi 쓰기·원격 동기화는 별도의 백업·충돌 해결·되돌리기 계약을 요구한다.

**완료:** 격리 테스트에서 두 번 클릭/재연결/거부/권한 만료/중지/재개/비용 한도 위반이 중복 실행이나 데이터 변조를 만들지 않으며, 쓰기 후 원본 시스템 재조회로 결과 확인.

## 5. 검증·인수 공통 기준

- 새 API는 모의 서버 계약 테스트(성공/401/403/오프라인/부분 실패/타임아웃)와 실제 지원 버전의 읽기 전용 스모크 테스트를 구분한다. 프로덕션에 테스트 작업을 만들지 않는다.
- `npm test`, `npm run build`, `npm run test:browser`; 1440/768/375px 및 200% 확대, 키보드/포커스, 로딩·빈 상태·오류·재시도·긴 한국어 제목·오프라인을 확인. 구현 후 최신 화면을 촬영해 이 참조의 정보 구조와 비교하되 로고·인물 오버레이·데모 수치를 복제하지 않는다.
- 비용·체크 수·기억 수·프로젝트 진척은 각각 **원본, 계산 규칙, 관측 시각, 커버리지**를 UI 또는 상세에 드러낸다. 퍼센트는 실제 분자/분모가 있을 때만 계산.
- 우선순위: P0 → P1을 첫 배포 단위로, P2(메모리)를 독립 작업, P3(Paperclip)을 실제 인스턴스 확인 후, P4(실행)를 별도 승인 후. P2와 P3은 P1 이후 병렬 가능하나 독립 데이터 경계를 유지한다.

## 6. 결정 필요 / 보류안

1. **가장 먼저 원하는 결과:** 운영 화면(P1), Obsidian 검색(P2), Paperclip 연동(P3) 중 우선순위를 정해야 한다. 추천은 P1.
2. Obsidian vault가 실제로 이 컴퓨터에 있고 읽기 권한을 줄 것인지, Omi가 어느 제품/데이터원인지 확인 필요. 경로와 자격증명은 채팅·문서에 쓰지 않는다.
3. Paperclip을 별도 실행 중인지, 계획만 원하는지 확인 필요. 현재 로컬 포트는 연결되지 않았다.
4. 회사/조직도/목표를 Paperclip 데이터로 읽을지, AgentOS 자체 데이터로 새로 모델링할지 선택. 추천은 **실제 Paperclip 사용 시 읽기 통합**, 미사용 시 조직도/가상 회사 생성 보류.

**기각:** 영상의 10 agents·1261 memories·$0 cost·62% progress를 시드하거나, CLI 미발견을 무조건 '실패'로 표시하거나, Paperclip과 Hermes 보드를 ID 매핑 없이 자동 동기화하는 방식. 이 계획을 승인해도 실행/연동/볼트 접근 권한을 자동으로 승인하는 것은 아니다.
