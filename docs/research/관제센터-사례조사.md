## 1) 한눈에 요약

1. **"관제센터"라고 부르는 화면은 대부분 같은 4칸 구성이다.** ① 지금 누가 일하는지(봇 상태) ② 돈이 얼마나 나가는지(비용·토큰) ③ 사람이 결정해야 할 것(승인 대기) ④ 최근에 무슨 일이 있었는지(활동 피드). Paperclip 자체 대시보드가 정확히 이 구성이다([Paperclip Dashboard 문서](https://docs.paperclip.ing/guides/day-to-day/dashboard)). OpenClaw용 Mission Control들도 같은 구성이다([builderz-labs](https://github.com/builderz-labs/mission-control), [TenacitOS](https://github.com/carlosazaustre/tenacitOS)).
2. **가장 많이 나오는 불만은 "사람이 뭘 해야 하는지 못 찾겠다"이다.** Paperclip GitHub에는 "승인 대기가 UI에서 안 보인다"는 이슈([#3821](https://github.com/paperclipai/paperclip/issues/3821))와 "Needs Your Attention" 패널을 추가하는 PR([#8638](https://github.com/paperclipai/paperclip/pull/8638))이 있다. Paperclip은 이후 승인·막힌 작업·실패한 실행·예산 경고를 한 줄로 모은 **Decisions(결정 큐)** 화면을 문서화했다([Decisions 문서](https://docs.paperclip.ing/guides/day-to-day/decisions/)).
3. **로그만 쌓아 두면 안 되고, 화면에서 바로 손댈 수 있어야 한다.** GitHub Copilot Mission Control은 실행 중에 지시를 바꾸는 "실시간 조정(steering)"을 핵심 기능으로 내세운다([changelog](https://github.blog/changelog/2025-10-28-a-mission-control-to-assign-steer-and-track-copilot-coding-agent-tasks/)). AutoGen Studio에는 일시정지·중지 버튼이 있다([문서](https://microsoft.github.io/autogen/stable/user-guide/autogenstudio-user-guide/)). 한국어 글 중에도 "모니터링에는 실행 중 개입이 필요하다"는 주장이 있다([blakecrosley](https://blakecrosley.com/ko/blog/ai-agent-monitoring-runtime-intervention)).
4. **개발자용 관측 도구(Langfuse·LangSmith·AgentOps·Phoenix·Helicone)는 "한 번의 실행을 단계별로 펼쳐 보는 화면"과 "품질 점수"가 강점이다.** 실행 폭포수(waterfall), 세션 리플레이, LLM 평가자(LLM-as-a-Judge) 점수, 비용 알림이 대표적이다. 비개발자 운영자에게는 이 중에서 "**봇별 비용**·**실패한 실행 상세**·**검수 통과율**" 정도만 쉬운 말로 바꿔 보여주면 된다.
5. **AgentOS에 비어 있는 곳(추정):** 이미 있는 화면은 조직도·프로젝트 허브(칸반)·커밋 기록·단체 대화방·승인 카드다. 여기에는 ① 봇 상태 신호등 ② 비용·토큰 화면 ③ 하나로 모은 "오늘 내가 할 일" 큐 ④ 이상 알림 ⑤ 작업 흐름 타임라인 ⑥ 검수 점수판이 없다. 다만 ①~③과 ⑤는 **Paperclip 기본 화면(Dashboard·Costs·Decisions·Work Timeline)에 이미 있다**. 그래서 새로 만들기 전에 "Paperclip 기본 화면을 쉬운 말로 다시 묶을지" 먼저 정해야 한다.
6. **추천 1순위(4번 표 참고):** ① "오늘 사장님이 할 일" 결정 큐 ② 봇 11개 상태 신호등 ③ 봇별·프로젝트별 비용 카드 ④ 이상 알림(단체 대화방 전송) ⑤ 검수 점수판.

## 4) AgentOS 추천 기능 후보 (우선순위순)

> 필요한 데이터는 요청서에 적힌 Paperclip API(agents / issues / comments / heartbeat-runs(usageJson 토큰) / routines / approvals) 기준이다. 그 외 엔드포인트가 필요한 곳은 **확인 필요**로 표시했다. 1~4는 Paperclip 기본 화면에 비슷한 것이 있으므로, 새로 만들기보다 **쉬운 한국어로 다시 묶고 AgentOS 화면에 넣는 것**을 우선 검토한다.

**선정 원칙**
- 이미 있는 것(승인 카드·검수봇·단체 대화방)을 **확장**하는 후보를 먼저 골랐다(1·4·5).
- 비개발자 운영자가 하루 1~2번, 30초 안에 확인하는 것을 기준으로 삼았다. 세션 리플레이나 LLM 평가자 같은 개발자용 기능은 뒤로 미루거나(7) 쉬운 말로 바꿨다.
- 1~3과 6은 Paperclip 기본 화면에 비슷한 기능이 있다. 만들기 전에 Paperclip 기본 화면을 그대로 연결할지, AgentOS식으로 다시 그릴지 결정해야 한다.

## 6) 한계·미확인

- **AgentOS 보유 여부는 추정이다.** 이번 조사에서는 AgentOS 코드와 실제 화면을 열어 보지 않았다. 3번 표의 "확인 필요" 항목은 실제 화면과 대조해야 한다.
- **Paperclip API 세부는 미확인:** heartbeat-runs에서 실행 로그 본문이나 단계별 이벤트를 얼마나 받을 수 있는지(후보 7), 루틴과 실행을 잇는 필드가 있는지(후보 8), 활동 로그 API가 있는지 확인하지 못했다. 대시보드 요약 API(`GET /api/companies/<id>/dashboard`)는 문서로 확인했다([CLI 문서](https://docs.paperclip.ing/reference/cli/dashboard)).
- **같은 이름의 다른 제품 주의:** "Paperclip AI"라는 이름으로 AI CEO "Zeus"가 등장하는 리뷰([kunalganglani](https://www.kunalganglani.com/blog/paperclip-ai-review-zero-human-company))는 오픈소스 paperclipai/paperclip(제작자 Dotta)와 다른 제품으로 보여 사례에서 뺐다. 동일 제품인지는 미확인이다. paperclip.inc는 2026-10-02 서비스 종료를 공지했는데([사이트](https://paperclip.inc/)), 이 역시 오픈소스 Paperclip과 같은 곳인지는 미확인이다.
- **원문 추출 실패:** agentops.ai 홈페이지(요청 한도 초과, 검색 요약만 확인)와 Langfuse Agent Graphs 문서(쿠키 화면만 추출)는 본문을 읽지 못했다. 그래서 해당 기능은 표에서 주장하지 않았다.
- **Arize Phoenix의 환각 탐지 템플릿 세부는 미확인**이다. 문서 개요의 "평가 테스트로 실패·회귀 탐지"까지만 확인했다.
- **서비스 상태 변화:** Vibe Kanban은 README에 서비스 종료 예정, Crystal은 Nimbalyst로 이전, builderz Mission Control은 alpha, AutoGen Studio는 운영용 아님이라고 각각 명시돼 있다. 디자인 참고용으로만 쓰는 것이 안전하다.
- **영상의 성격:** 한국어 후기 영상([Jr7IcBa0Ik8](https://www.youtube.com/watch?v=Jr7IcBa0Ik8))은 자동 자막으로 확인했고, 끝에 코칭 프로그램 홍보가 있다. Metics Media 영상의 한국어 자막은 번역본이다. 이 영상에는 Hostinger 제휴 링크가 있다.
