# 비서실장 "복잡한 요청" 처리 과정 분석 (2026-09-29)

계획: `docs/chief-process-audit-plan.md` · 스크립트: `scripts/chief-process-audit.py` · 증거: `docs/evidence/chief-process-audit-20260929.json`(파일명·분류·시간만, 명령 원문·비밀값 없음).
모든 수치는 Paperclip 실행 기록과 비서실장 프로필(pc-ebb0943f) 세션 DB에서 읽기 전용으로 뽑았다. 대상 요청은 모두 추론 강도 **최대**(max)에서 실행됐다.

## 1. 한눈에

| 요청 | 계획서 올리기까지 | 그중 기술 조사 | 조사 도구 호출 | 승인 카드 이후 비서실장 시간 | 하위 작업 |
|---|---:|---:|---:|---:|---|
| HER-20 피그마 로그인 | **82.7분** | 73.2분 (88%) | 122 / 147 | 17.0분 | 없음 (비서실장이 직접 수행) |
| HER-21 검수 봇 | **105.9분** | 89.1분 (84%) | 106 / 135 | 13.1분 | 2개 |
| 비교: HER-11 블로그 제목 | 9.9분 | 2.8분 (28%) | 12 / 41 | 41.2분 | 1개 |
| 비교: HER-17 유튜브 준비 | 97.3분 | 69.2분 (71%) | 141 / 176 | 86.2분 | 1개 |
| 비교: HER-19 스킬 부여 | 131.6분(계획서 없음) | 96.4분 (73%) | 161 / 237 | — | 없음 (직접 수행) |

- 실행 시간의 90~94%는 모델 응답 대기다. 호출 1번에 약 14~15만 토큰 문맥, 평균 31~44초.
- 즉 느린 이유는 **"호출 수(조사량) × 호출당 시간(max 강도·큰 문맥)"** 이다. 강도는 이미 high로 내렸고(`e03276c`), 남은 큰 축은 **조사량**이다.
- 단계 시간 합계와 실제 실행 시간 대조: 모든 실행에서 95% 이상 일치(`AUDIT_SUM_OK`).

## 3. 조사 행동 판정 (계획서 게시 전 호출)

판정 규칙(스크립트에 고정): A 필수(조직·이슈·계획 작성·지시) / D 기술 조사 중 계획서에 인용된 것 / C 기술 조사 중 계획서에 흔적이 없는 것 / E 비서실장이 실행자 일을 함 / 보류(대상 파일을 특정 못 함).

| 요청 | A 필수 | D 인용됨 | C 흔적 없음 | E 직접 실행 | 보류 |
|---|---:|---:|---:|---:|---:|
| HER-20 | 25 | 32 | **49** | 2 | 39 |
| HER-21 | 27 | 17 | **61** | 6 | 24 |

- "인용" 판정은 파일명이 계획서에 나오는지로 본다. 파일명 없이 결론만 반영된 조사도 C로 잡히므로 **C는 낭비의 상한**이다.
- 사람 확인: 무작위 표본 12건을 직접 봤다. C 판정 예 — Paperclip `issue-execution-policy.js`, `issue-assignment-wakeup.js`, `auth.js`, `self-serve-mcp-research.js`, `hermes_constants.py`, 검증 서버 실험 스크립트 `review_flow_test2.py` — 모두 구현 담당이 알아내면 되는 내부 동작이었다. D 예 — `mcp_oauth.py`는 계획서의 "확인한 사실"에 실제로 쓰였다. 표본에서 판정이 틀린 건 없었다.
- **중복**: HER-21 계획 전 비서실장이 본 파일 62개 중 6개(org.ts, worker.ts, 검증 스크립트 3개 등)를 코드구현·검수 봇이 나중에 다시 봤다. 중복 자체는 작다. 문제는 중복보다 **아무 봇도 필요 없던 서버 내부 조사**가 크다는 것.
- 반대로 A(조직 확인·과거 계획 참고·계획서 작성·지시)는 HER-20 8.8분, HER-21 15.7분이면 끝났다. 사장님이 정의한 비서실장 업무(계획·배분·봇 생성)는 이 정도 시간이면 된다.

## 4. 분배 점검

- **취소 4건은 잘못된 배정이 아니다.** 4건 모두 `issue_reassigned`이고, 끝난 시각이 해당 봇의 "제출/반려" 댓글과 같은 초다. 검수 단계에서 작업이 봇→검수 봇→봇으로 넘어가며 Paperclip이 이전 실행을 "취소"로 닫은 정상 흐름이다(계획서 초안의 추정 정정). 다만 화면에 "취소"로 보여 오해를 부른다.
- **비서실장이 실행자 일을 한다.** HER-20(로그인 4건), HER-19(스킬 부여), HER-21(병합·운영 배포·측정)을 비서실장이 직접 했다. 계획·배분 역할과 섞여 창구가 오래 막힌다.
- 봇 생성은 필요한 곳에서만 했다(HER-21 검수 봇 1개). 문제없음.

## 5. 지침 비판 (근거 포함)

1. **"계획 전에 사실을 모아라"에 상한이 없다.** 비서실장 스킬 §1 "Gather facts before planning"과 계획 템플릿의 `## 확인한 사실`(내용 | 확인한 곳) 표가 "가능한 한 다 확인해서 적어라"로 작동한다. 모르는 것을 "가정"으로 두는 길이 있지만, 비서실장은 거의 모든 기술 질문을 직접 확인했다(HER-21 CMP-3~7 실험 31분).
2. **실험을 계획 단계에서 한다.** 검증 서버에 작업을 만들어 돌려 보는 일은 구현·검증 봇의 일이다. 승인도 받기 전에 31분을 썼다.
3. **감독 단계가 검수 봇과 겹친다.** 스킬 §4 "모든 기준을 코드로 직접 확인, 봇의 확인표는 주장일 뿐"은 검수 봇이 생기기 전 규칙이다. HER-21에서 검수 봇이 기준 7개를 직접 재실행해 승인한 뒤에도 비서실장이 다시 병합·측정했다. HER-20 감독 실행 14.6분 중 7.2분이 봇 프로필 재점검이었다.
4. **비서실장에게 실행 금지가 없다.** 설치·로그인·병합·배포를 직접 하지 말라는 규칙이 없어, "빠른 길"로 직접 처리하고 창구를 오래 점유한다.
5. **문맥이 크다.** 매 호출 약 14~15만 토큰. 매번 싣는 것: paperclip 스킬 59KB, 비서실장 스킬 22.5KB, SOUL 15KB. 요청에 따라 hermes-agent(13KB)·figma(16.6KB) 스킬도 올린다. 호출 수가 많을수록 이 비용이 곱해진다.

## 6. 개선 후보 (적용 전, 승인 필요)

| # | 바꿀 것 | 기대 효과 | 비교 방법 |
|---|---|---|---|
| 1 | 계획 전 조사 범위를 **조직·봇·과거 비슷한 요청·요청 문장에 나온 대상**으로 제한. 기술 내부(서버 코드·로그·Hermes 소스)는 읽지 않고 "가정/확인할 것"으로 적어 첫 하위 작업(조사 담당 봇)에 넘김 | 계획까지 83~106분 → 10분 안팎(HER-11 수준, high 실험 1분) | 같은 종류 요청을 high에서 실행, 계획 게시까지 시간·호출 수·계획 품질 |
| 2 | 계획 단계에서 실험·검증 서버 사용 금지 | HER-21 31분 제거 | 위와 같음 |
| 3 | 비서실장 직접 실행 금지(설치·로그인·병합·배포·파일 수정은 봇에 배정, 담당이 없으면 봇 생성) | 창구 점유 시간 감소, 역할 명확 | 승인 뒤 비서실장 실행 시간 |
| 4 | 검수 단계가 있는 하위 작업은 검수 봇 승인 = 기준 충족으로 보고, 비서실장은 조직 수준 기준만 확인 | 감독 5~15분 → 1~2분 | 감독 실행 시간, 검수 누락 여부 |
| 5 | "취소"로 보이는 검수 넘김을 화면에서 "넘김"으로 표시 | 오해 방지 | 화면 확인 |
| 6 | 매번 싣는 스킬 크기 점검(특히 paperclip 59KB) | 호출당 시간 감소 | 호출당 캐시 토큰·시간 |

1~4는 비서실장 지침(`scripts/setup-chief-single-window.mjs`)과 비서실장 스킬 수정이므로 사장님 승인 후 백업하고 적용한다.

## 7. 한계

- 분석 대상 요청은 모두 max 강도. high에서의 조사량은 아직 실측 전이다(강도만 바꾸면 호출 수도 줄어드는지는 개선 후 첫 실제 요청으로 확인).
- 분류는 파일·명령 패턴 기반이다. 보류가 호출의 17~27%다.
- HER-4·HER-6은 세션 기록이 없어(초기 설정) 시간만 비교했다.
