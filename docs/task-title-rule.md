# 작업 제목 규칙

상태: **적용 중 (2026-09-28)** — 새 요청·새 하위 작업부터. 기존 HER-1~19 제목은 그대로 둔다.

목적: 사장님이 `HER-18` 같은 번호를 몰라도 제목만 보고 **어느 일의 어느 부분인지** 알 수 있게 한다.

## 형식

```
프로젝트 › 작업묶음 › 세부작업-순번
```

| 항목 | 규칙 |
|---|---|
| 구분 기호 | ` › ` (앞뒤 띄어쓰기 한 칸) |
| 요청 제목 | 1~2칸. 예: `홈페이지 제작 › 디자인-1` |
| 하위 작업 제목 | 부모 제목 **전체**(순번 포함) + ` › 세부작업-순번`. 최대 4칸 |
| 칸 이름 | 결과물이 보이는 짧은 명사, 한 칸 20자 이하. 예: `샘플보고서`, `디자인시안`, `코드구현` |
| 순번 `-N` | 같은 제목을 **다시 만든** 횟수 (기존 같은 제목의 가장 큰 순번 + 1). 실행 재시도는 순번을 올리지 않음 |
| 넣지 않는 것 | `요청:` 머리말, 상태 말(취소·재시작·완료·진행 중 — 상태는 배지로 보임), HER 번호 |
| HER 번호 | 그대로 유지. 링크·실행 기록 연결용 보조 표시 |

## 예시

| 기존 방식 | 규칙 적용 |
|---|---|
| 요청: 유튜브 분석 준비 — 취소한 작업과 분리하여 새로 시작 | `유튜브분석 › 기능준비-2` |
| 영상 샘플 보고서 — 유튜브 분석 준비 (마죽 영상) | `유튜브분석 › 기능준비-2 › 샘플보고서-1` |
| 가을 발효 요리 블로그 제목 5개 + 한 줄 설명 작성 | `학원블로그 › 제목아이디어-1 › 가을발효제목-1` |
| (사용자 예시) 홈페이지 제작_홈페이지디자인_히어로배너디자인-1 | `홈페이지 제작 › 디자인-1 › 히어로배너-1` |

## 누가 어디서 적용하나

| 단계 | 담당 | 구현 위치 |
|---|---|---|
| 요청 접수 시 임시 제목 | 창구(자동) | `plugins/agentos-control/src/task-title.ts` `requestTitle` → `chief.ts` 요청 생성. 첫 줄에서 `요청:` 제거, 20자 안팎으로 자르고 `-순번` 부여. 첫 줄에 `›`를 쓰면 그 경로(최대 2칸)를 그대로 사용 |
| 계획 저장 시 정식 제목 | 비서실장 | 지시문 "작업 제목 규칙" 블록(`scripts/setup-chief-single-window.mjs`) — 요청 제목을 `프로젝트 › 작업묶음-N`으로 고침 |
| 하위 작업 생성 | 비서실장 | 같은 블록 — 부모 제목 전체 + ` › 세부작업-N` |
| 규칙 검사 함수 | 코드 | `checkTitle`, `childTitle`, `nextSeq` (`task-title.spec.ts`로 검증) |

## 하지 않는 것

- 기존 작업 제목 일괄 변경 (사장님 지시 전까지).
- HER 번호·내부 ID 변경.
- ~~화면(UI) 표시 방식 변경~~ → 2026-10-04 적용: 플러그인 화면은 경로를 작게, 이름을 굵게, 2번째부터 `N회차`로 보여 준다.

## 2026-10-04 추가 (사장님 결정)

- **순번 정리**: 기존 규칙 제목에 빠진 `-N`을 붙였다. 다시 한 작업(`… 다시 작성`, `(r2)`)은 `다시`/`(rN)`을 빼고 같은 이름의 다음 순번으로 쓴다. 예: `블로그 제목 후보 3개 작성-1` → 재작업은 `…작성-2`.
- **상위 이름이 바뀌면 하위도 같이**: `agentos.title-sync` 플러그인이 작업 생성·변경 때 하위 제목의 경로 부분(상위 전체 제목)을 자동으로 맞춘다. 하위의 자기 이름은 건드리지 않는다. 자유 형식 상위(규칙 이전 제목)의 하위는 손대지 않는다.
- `[보관]` 같은 머리표는 경로 앞에 그대로 둔다.
