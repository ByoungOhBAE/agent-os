# 단체방(Group Chat) 통합 관제 — 초기 계획과 시험 이력

상태: **초기 계획 보존 / 연결 코드 존재 확인 (2026-09-28).** `server/rooms.mjs`, `plugins/agentos-control/src/ui/rooms.tsx`에 구현이 있습니다. 아래 “방 0개”, “draft”, “결정 필요”는 2026-09-26 당시 상황이며 현재 상태가 아닙니다. 단일 창구 모드에서는 직접 방 지시·생성을 제한합니다. 데스크톱 종료·재부팅 기준 전체를 이번에 재검증한 것은 아닙니다. [재검수 근거](../plugins/agentos-youtube/OPERATIONS-AUDIT.md).
대상: AgentOS(Paperclip 호스트 + `agentos.control` 플러그인 + 로컬 BFF 4200)
요청(원문): "여러 에이전트 봇을 업무,역할 별로 나누어서 생성하고 헤르메스 데스크톱 앱에서 처럼 단체 톡을 만들어서 작업하는 기능도 대시보드에서 실시간으로 보고 기능 동작하게 … 헤르메스 데스크톱을 꺼도 작동하는 통합 관제 시스템"

## 1. 확인한 사실 (이번 세션 실측, 읽기 전용)

| 사실 | 근거 |
|---|---|
| Hermes v0.21.4에 **데스크톱 없이 도는 단체방 엔진**(hosted room)이 있다 | 공식 문서 Bot Mode "Rooms keep running when you close the Desktop", `groups.capabilities` → `driver: true` |
| 단체방 조작 API가 18개 있다: 생성·목록·상태·보내기·로그·중지·승인·재시도·해산 등 | 실행 중인 대시보드(9119) `/api/ws` JSON-RPC `groups.capabilities` 응답 |
| `hermes gateway run`이 로그인 시 자동 시작되고, 이 프로세스가 단체방 엔진(worker)을 계속 살려 둔다 | 시작프로그램 `Hermes_Gateway.vbs`, `gateway/run_startup.py` `_hosted_room_worker_watcher` |
| **지금 엔진에 등록된 단체방은 0개다** | `groups.list` → `[]`, `shared-state.db`·`state.db`의 `hosted_rooms` 0행 |
| 기존 단체방 "림버스 컴퍼니 헬퍼 개발방"(봇 4, 기록 24줄)은 데스크톱 쪽 기록에만 있다 | 기본 프로필 `profile.yaml` → `ui_meta.hermes-bots-groups.rooms` |
| 그래서 지금 AgentOS는 그 방의 **기록만** 보여 준다 | 기존 `/api/hermes/bots` 읽기 전용 경로 |

결론: 원하는 기능은 **만들 수 있다.** 새 엔진을 새로 만들 필요는 없고, Hermes에 이미 있는 "데스크톱 없이 도는 단체방 엔진"을 AgentOS에서 조작하도록 연결하면 된다.

## 2. 목표
1. AgentOS에서 단체방을 만들고(봇 2~6), 메시지(@멘션 포함)를 보내고, 봇들의 답을 **새로고침 없이** 본다.
2. 진행 중 멈춤, 봇이 묻는 승인(이번만/이 세션/항상/거절), 실패 재시도를 AgentOS에서 처리한다.
3. **Hermes 데스크톱을 완전히 꺼도** 1·2가 동작한다.
4. 업무·역할별 봇을 AgentOS에서 만든다(이름·직함·역할 설명·모델).
5. 엔진이 꺼져 있으면 "방 없음"이 아니라 "단체방 엔진 꺼짐"으로 분명히 보인다.

## 3. 비목표 (이번 범위 밖)
- Hermes 원본 수정. 공개된 JSON-RPC와 CLI만 쓴다.
- 여러 컴퓨터에 걸친 단체방(peer). 이 PC 한 대만 대상으로 한다.
- 데스크톱 쪽 옛 방 기록을 새 엔진으로 자동 이전. 옛 방은 읽기 전용으로 계속 보이고, 같은 구성원으로 새 방을 만드는 버튼만 둔다.
- 봇별 Claude/Codex **구독 로그인 대행**. Hermes는 OAuth 로그인을 프로필 사이에 복사하지 않으므로, 구독 모델을 쓰는 봇은 사용자가 한 번 로그인해야 한다(이 단계는 안내 화면으로 제공).
- 외부(LAN·인터넷) 공개. 계속 loopback 전용이다.

## 4-1. 0단계 실측 결과 (2026-09-26, 무료 모델 solar-pro4:free 시험 봇 2개)
- 데스크톱 켜짐: 방 생성·전송 → 봇 답 12초·24초, 해산 성공.
- **데스크톱 완전 종료(Hermes.exe 0개)**: `gateway run`·8645는 생존, **9119 대시보드는 같이 종료**.
  직접 띄운 `hermes dashboard --port 9129 --isolated`로 방 생성·전송 → 봇 답 8초·14초(서로 @멘션하며 대화), 해산 성공.
- 결론: A2 확인됨. A1은 "데스크톱과 같이 꺼짐"으로 확인됨 → 4단계(실행기가 JSON-RPC 서버를 따로 띄움) 필수.
- 부수 발견: 9119가 꺼지면 기존 AgentOS의 Hermes 기능(세션·스킬·칸반 등)도 같이 멈춘다. 같은 조치로 해결된다.

## 4. 가정 — 착수 전에 0단계에서 먼저 확인
- A1. 9119 대시보드(`hermes dashboard --isolated`)를 **누가 띄우는지 모른다**(부모 프로세스 종료됨). 데스크톱을 끄면 같이 꺼질 수 있다. 꺼진다면 AgentOS 실행기가 `hermes serve` 또는 대시보드를 따로 띄워야 한다.
- A2. 데스크톱이 꺼진 상태에서 방의 다음 차례를 `gateway run` 쪽 worker가 이어받는다(문서상 driver lease 이동). 실제 방 하나로 확인해야 한다.
- A3. 대시보드 접속 토큰은 loopback 모드에서 페이지에 들어 있는 세션 토큰을 BFF가 서버 안에서만 읽어 쓴다. Hermes가 인증 필수 모드로 바뀌면 이 방식은 막히므로, 그때는 내부 자격(`?internal=`) 경로를 다시 조사한다.
- A4. 실시간은 `groups.log`를 커서(단조 증가 로그)로 2초마다 이어 읽는 방식으로 충분하다. 푸시 스트림은 나중 과제다.

## 5. 구조 (초안)
```
Paperclip 화면(통합 관제 › 단체방 탭)
   └─ agentos.control 플러그인 worker  (토큰 모름)
        └─ BFF 4200  /api/control/rooms/*   ← 허용 목록 필드만, 로그 마스킹
             └─ Hermes JSON-RPC /api/ws  groups.* (loopback, 토큰은 BFF 메모리에만)
                  └─ 단체방 엔진: gateway run worker ↔ shared-state.db (데스크톱과 공유)
```
- 데스크톱을 다시 켜면 같은 방·같은 기록이 데스크톱에도 보인다(같은 DB를 쓰기 때문).
- 보내기는 `idempotent_send` 키를 붙여, 재연결 중 두 번 눌러도 한 번만 실행되게 한다.

## 6. 단계
| 단계 | 내용 | 산출물 |
|---|---|---|
| 0 검증 스파이크 | A1·A2 확인. 데스크톱을 끈 상태에서 싼 모델의 시험 봇 2개로 방을 만들고, 한 번 보내고, 답 확인 후 해산 | 관찰 기록(실제 토큰 소모 있음 → 승인 필요) |
| 1 보기 | 방 목록·구성원·기록·진행 상태, 2초 이어 읽기, 엔진 상태 표시, 옛 방 읽기 전용 | BFF 라우트 + 단체방 탭 |
| 2 조작 | 방 만들기, 보내기(@멘션), 멈춤, 승인 4종, 재시도, 이름 변경 | 같은 탭의 입력창·버튼 |
| 3 봇 만들기 | 역할별 봇 생성(이름·직함·설명·SOUL 역할 지침·모델), 구독 로그인 필요 시 안내 | 봇 생성 창 |
| 4 상시 가동 | AgentOS 실행기(바탕화면 아이콘)가 단체방 엔진·JSON-RPC 서버를 확인하고 없으면 띄움 | 실행기 갱신 |
| 5 운영 반영 | 백업·롤백 스크립트로 BFF·플러그인 반영, 1440/768/375 점검 | 보고 |

## 7. 수용 기준
- AC1. Hermes.exe 프로세스가 **하나도 없는 상태**에서 AgentOS로 방 생성 → 메시지 전송 → 봇 2개의 답이 화면을 새로고침하지 않고 10초 안에 나타나기 시작한다.
- AC2. 진행 중 "멈춤"을 누르면 다음 차례가 시작되지 않는다.
- AC3. 봇의 승인 요청이 AgentOS에 뜨고, 버튼 한 번으로 응답된다.
- AC4. 데스크톱을 다시 켜면 같은 방과 기록이 보인다.
- AC5. 엔진이 꺼져 있으면 "단체방 엔진 꺼짐"과 다시 켜기 방법이 보이고, 빈 목록으로 보이지 않는다.
- AC6. 토큰·키가 화면, 플러그인 번들, BFF 로그에 나타나지 않는다(검사 스크립트).
- AC7. 1440/768/375에서 넘침·잘림 0, 한국어 줄바꿈 정상, 콘솔 오류 0.
- AC8. PC 재부팅 후 데스크톱을 열지 않고 AC1이 된다 — 재부팅 시험은 따로 보고한다.

## 8. 검증 방법
- BFF: 가짜 JSON-RPC 서버로 계약 테스트(허용 필드, 토큰 미노출, 엔진 꺼짐 → 503).
- 실측: 0단계와 같은 시험 봇 2개로 AC1~AC4를 실제로 돌린다(데스크톱 종료 상태 확인 후).
- 화면: 기존 게이트 스크립트 방식으로 5개 너비·상태 캡처 확인.

## 9. 위험
- **비용**: 메시지 한 번에 최대 3바퀴 × 구성원 수만큼 모델이 호출된다. 방마다 모델·바퀴 제한을 화면에 표시한다.
- **메모리**: 봇 하나당 백엔드 약 60MB. 동시에 여러 방을 돌리면 늘어난다.
- **업그레이드**: Hermes 버전이 바뀌면 `groups.*` 계약을 다시 확인해야 한다(capabilities로 자동 점검).
- **데스크톱과 동시 조작**: 같은 방을 양쪽에서 보내면 순서가 섞일 수 있다(엔진이 lease로 한 번에 하나씩 처리).

## 10. 결정 필요 (사용자)
1. 0단계 실측에 쓰는 시험 봇 2개의 모델(싼 모델로 몇 턴, 토큰 소모 있음) 승인.
2. 옛 방 "림버스 컴퍼니 헬퍼 개발방": 읽기 전용 유지 / 같은 구성원으로 새 엔진 방 만들기.
3. 3단계(봇 만들기)를 이번에 포함할지, 1·2단계 후로 미룰지.

## 11. 기각한 선택지
- 데스크톱 앱을 백그라운드로 계속 켜 두기: 사용자가 원하는 "데스크톱 없이"가 아니고, 데스크톱이 꺼지면 같이 멈춘다.
- `shared-state.db`에 직접 쓰기: 엔진의 lease·순서 보장을 우회해 방을 망가뜨릴 수 있다. 읽기도 JSON-RPC로 한다.
- 우리가 단체방 엔진을 새로 만들기: Hermes에 이미 있고, 데스크톱과 기록이 따로 놀게 된다.
